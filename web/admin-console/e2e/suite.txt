# Which spec files the CI browser-journey job runs — and, for every one it does
# not, why.
#
# The suite was written against a MOCKED console and never executed until this
# branch wired it into CI (playwright.config.ts had no `setup` project, so
# nothing ever signed in). The first real run, against a stack of Postgres,
# Redis and the eight services, measured 448 passed and 282 failed. Three
# causes were mechanical and are fixed in the specs; the rest is a long tail of
# assertions against fixtures, hosts, routes and DOM shapes the product does
# not have. None of those specs is deleted and none is `test.skip`'d —
# `npm run test:e2e` still runs all of them — but a gate that is red on arrival
# is a gate that gets switched off, so the job runs what holds.
#
# Format: `run <spec>` or `hold <spec> <reason>`. Every file in e2e/ must
# appear exactly once; scripts/check-e2e-suite.sh (self-tested, enforced in the
# UI safety guards job) fails if one is missing, if a hold has no reason, or if
# a listed file has been renamed away. The register is meant to SHRINK on the
# hold side: each entry names what has to be true for it to move to `run`.
