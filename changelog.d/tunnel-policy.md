### Added
- **The tunnel policy reaches the device.** The organization's network policy is now sent to the agent as `org_network_policy` in `/agent/config` (only to an agent whose enrolment is active, never a pending or suspended one, since it carries internal ranges) and in the answer to every posture report, with `corporate_cidrs` (the CIDRs and IP-address hosts of the enabled network resources, sent while the block is on) and a `version`, a digest of everything the device acts on. The agent applies what its platform can: **always on** turns the tunnel on whatever `agent.json` says and keeps the tunneler restarted, with no user override; **split tunnel** is how the bundled tunneler always runs; **block direct corporate access** loads an nftables table (`inet openidx_direct`) on Linux when the agent runs as root, rejecting traffic to the corporate ranges that does not leave through the tunneler's interface (root's own traffic is let through, so the tunneler and the agent can reach the controller and the routers). What a device cannot enforce it reports instead of claiming: a full tunnel everywhere (`full_tunnel`), and the block on Windows, macOS and an unprivileged Linux agent (`block_direct`). `docs/AGENT-TUNNEL.md` has the per-platform table.
- **The agent says how it applied the policy.** `tunnel_status` now carries `mode`, `policy_version` (left out while applying failed), `policy_gaps` and `last_error`. The server keeps the applied version in `enrolled_agents.tunnel_policy_version` with `tunnel_policy_applied_at` (migration 237). `GET /api/v1/access/agents` returns them with `tunnel_policy_state` (`applied` or `pending`), and `GET/PUT /api/v1/access/network-policy` return the current `version` and how many active devices have `applied` it, are `pending`, or report no tunnel.
  - **Console:** Agent Fleet shows **Policy applied** / **Policy pending** beside each device's tunnel state, and the tunnel badge's title adds the mode, what the device cannot enforce and its last error. The Network policy card counts the devices that run the current version, and says when a switch is one some devices cannot enforce.

### Changed
- **The agent's tunnel report is read as the agent sends it.** The Go agent sends its services as names and its state as `connected`/`degraded`/`off`/`not_installed`; the server expected objects and `up`/`down`, so a report from a connected tunnel carrying a service failed whole with a 400, and `connected` was stored as `unknown`. Both shapes are accepted now, `connected` and `degraded` are stored as `up` and `down`, and `off` (a device whose tunnel is not enabled) is its own state, shown as **Off** and no longer counted by `openidx_tunnel_agents_down`.
