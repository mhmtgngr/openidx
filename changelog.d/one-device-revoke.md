### Security
- **A device is revoked the same way from every page.** Agent Fleet's revoke set the device's status and deleted its overlay identity and stopped there: the device's refresh-token families went on refreshing, its known device stayed trusted and its live circuits were not severed, while the same device revoked from the user's page (Access 360) lost all of them. Both now run one device revoke, which severs the circuits, deletes the identity, revokes the row, untrusts the known device and revokes the bound refresh-token families and sessions; the fleet route's answer carries the result. The kill switch gains `revoke_devices`: with it, every device the user enrolled is revoked the same way; without it the devices keep their identities with their circuits severed, as before, so a device can be re-assigned.
