### Security
- **Enrolling with another device's fingerprint no longer takes that device's record.** An enrolment that named an existing agent's fingerprint used to take its row whoever sent it: it rotated the real agent's token (so the agent stopped working), set a suspended device active, and replaced or dropped its device key; a wizard code any user can make for themselves was enough. The row is now taken only on proof: the request is signed with the key the device already holds (the desktop agent signs its re-enrolment as the agent it was), or the row holds no key and an operator token or the row's own user enrols it. Otherwise the device is enrolled as a new agent without the fingerprint, the existing row is left as it was, and the attempt is audited as `agent.enroll_denied` against the agent it named.
  - **Upgrade note:** a device that holds a key and enrols again from an agent older than this release, or whose key was lost, becomes a new agent; revoke the old row from Agent Fleet. A user's OAuth enrolment of a machine an operator token enrolled is a new agent too.
