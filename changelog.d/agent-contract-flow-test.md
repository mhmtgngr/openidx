### Added
- **The agent's conversation with the server is tested end to end, with the bodies the contract publishes.** `api/agent-v1/examples/` holds the exact JSON a desktop agent and an Android agent send to enrol and to report, and `TestAgentContractFlow` (`internal/access`, on the migrated schema, in CI) plays them against the real handlers: enrol, poll the config, post a signed posture report (an unsigned report from a device with a key is refused), list the fleet as an operator, revoke the device, and watch the config, report and device-key routes all answer 403 `agent_revoked`. It found one defect on the way: an active device with no configured checks was handed a config without `enrollment_status`, which the Go agent read as "cannot check with the server"; the config now carries it.
